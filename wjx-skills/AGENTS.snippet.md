## WJX 个人开发流程

- 适用于所有代码项目。用户提出新的业务功能、页面或明显的能力扩展，且尚未指定工作方式时，在创建方案文件或修改业务代码前先询问一次是否使用 WJX 流程，提供“使用 WJX 流程”和“按现有方式处理”两个选项；等待明确选择期间可只读调查，不把沉默当作同意。
- 用户选用后读取 `wjx-dev`，按 `wjx-askme → 需求共识确认 → wjx-plan-to-doc → 方案确认 → wjx-execute → wjx-review → wjx-finish` 推进。Review 由 Open Code Review（`ocr`）执行并复核结果；每次只加载当前阶段及必要依赖，直接调用某个 WJX Skill 视为已经选择该阶段的工作方式。
- 两个确认点分别对应可审阅的需求共识和具体实施方案。选择 WJX 或回答业务问题不代替确认；需求确认不代替方案确认。已有针对同一范围、当前版本的明确确认继续有效，不因换阶段或换聊天重复询问。
- 同一需求的补充、继续实施和验证沿用已有选择。纯问答、问题诊断、既有 Bug 修复、局部文案或样式调整不主动触发整套流程。用户拒绝、明确使用原版 OpenSpec 或其他工作方式时遵从，不自动改成 WJX。
- 只要求讨论、方案、执行或 Review 时遵守该范围；完整流程在方案确认后继续实施与验收，必要验证完成才同步规范并归档。重要范围或方案变化仅重开受影响部分的确认。
- 各项目的 AGENTS.md 决定源码命名、资料入口、技术约束、构建和设备职责等具体要求。WJX 不沿用某个旧项目的路径、索引脚本或权限；任务清单不自动授予提交、发布或设备操作权限。
