# 需求、设计与实现核对

使用 [CLI 与路径约定](../../wjx-dev/references/openspec-cli.md) 解析同一个 change；读取 status 和 apply instructions 指向的实际资料。此过程只核对，不执行 apply、修改 checkbox 或归档。

## 完整性

- 用 `taskTrackingConfigured` 判断当前 schema 是否跟踪任务。未配置则标记不适用；配置后 `unavailableTrackingFiles` 非空、任务无法读取或只有不可评估的计数时，标记未验证，不能把部分 `tasks/progress` 当全量完成。
- 使用聚合后的 `tasks` 与 `progress`，不要假定任务一定在顶层 tasks.md。未完成任务按实际必要性报告；checkbox 只是记录，仍需实现与验收证据。
- spec 产物按 schema 的路径定义识别，不假定 ID 必为 specs。明确 skipped 或未定义为不适用；本应存在而不可读、空白或无可用要求则为未验证。

## 增量语义

- ADDED / MODIFIED：按新要求与场景核对真实入口、行为和异常边界，给出实现位置与可用检查证据。源码里出现关键词不足以证明行为可达。
- REMOVED：从同一 capability 的主规范读取要删除行为的原文和场景，再核对行为确已撤除；不能只搜索要求名称，更不能建议把被删除要求实现回来。已同步时在实际资料仓库的 Git 历史恢复基线，不能用代码仓库的历史代替 Store 历史。无法取得有实质内容的基线则标记未验证。
- RENAMED：从 FROM（或已同步的 TO）获取原行为，检查 TO 保留该行为；不要求代码符号随文档改名。TO 同时存在 MODIFIED 时以修改后的要求核对。
- 匹配要求标题使用区分大小写的规范名称；移除末尾 Markdown 关闭符号时保留 `C#` 等名称自身的 `#`。相似名称不能冒充相同要求。
- 只有删除或改名的 change，其新增/修改行为映射和新场景检查不适用；删除/改名本身仍须核验。没有可解析要求的空资料不能按“不适用”算通过。

## 设计与证据

核对明确的架构、接口、状态所有者、失效条件和依赖选择，以及当前项目约束。设计是 schema 中可选且明确省略时为不适用；本应有但缺失则报告限制，不补造设计决定。

每一项分别记录已核对、发现问题、未验证或不适用。只有任务记录时只能证实任务记录本身，不能宣称需求行为或代码模式全部通过。未实际执行的构建、测试、设备场景保持待验证，并交 FINISH 按已确认的必要验收处理；不把可选资料或额外测试升级成新门槛。
